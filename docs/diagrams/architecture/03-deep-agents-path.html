Deep Agents path: planning without write access

In plain words

Only requests the router labels as planning reach this path, for example comparing leave options around holidays. Simple questions never pay for planning, which is slower than the normal tool loop.

The planner writes a short to-do list and delegates to two sub-agents: one reads policy, one does leave calculations. The sub-agents run on the faster Haiku model. They can only use read tools, with a shared budget of 12 tool calls, 3 sub-agent runs and 22 seconds, after which the planner must answer with what it has.

The planner's answer passes the same verifier as every other answer and is shown as options only. It cannot prepare or submit a leave request: that tool is not offered, and the guard also refuses it, and the library's file and shell tools, at the moment they are called. If planning fails or returns nothing, the normal tool loop answers instead.

Architecture · Security and data

Identity, tools, domain rules and data: the trust boundary

In plain words

The model is treated as untrusted. It can suggest a tool and its arguments, such as dates or a leave type, but the tool schemas contain no employee ID or role, and unknown arguments are rejected. The server adds identity from the verified login token, and offers each role only its own tools. The model can prepare a leave draft but cannot submit it: only the employee's confirmation does.

Tools call two things: pure domain rules (working days, accrual, eligibility R1 to R10) that never touch the database or the clock, and repositories that run parameterized SQL filtered by employee or manager ID. A manager can only ever see direct reports because the filter is in the query itself.

Every tool call and every write is recorded in an audit log with the user, inputs, outputs and trace ID.
